# Potion.Tray（トレイ常駐アプリ）

Potion.Tray は、Windows の状態を定期的に点検し、許可された安全な修復だけを自動実行するトレイ常駐アプリです。点検結果は履歴に保存され、必要に応じて通知されます。

## 動作の仕組み

1. 設定された間隔で、ディスク、重要サービス、コンポーネントストア、メモリ、再起動保留、DNS を点検します。
2. 問題が見つかった場合、自動修復の設定、管理者権限、1日の試行上限を確認します。
3. 実行したコマンド、結果、出力末尾を履歴へ保存します。
4. 修復が成功した場合は同じ点検を再実行し、問題が残っていれば未検証として履歴に記録します。
5. 通知モードに応じて Windows のバルーン通知を表示します。

スリープ復帰、ユーザーのログオン・ロック解除、ネットワーク復帰時には即時点検を開始します（イベント連発時は2分間デバウンス）。同じユーザーで二重起動した場合は、既存インスタンスの履歴画面を開きます。

## 点検と修復

| 点検 | 既定の間隔 | 修復 | 管理者権限 |
| --- | ---: | --- | :---: |
| ディスク空き容量 | 毎サイクル | 一時ファイル削除、任意でコンポーネント整理 | 不要（一部は必要） |
| 重要サービス | 毎サイクル | 停止サービスの再起動 | 必要 |
| コンポーネントストア | 12時間 | DISM RestoreHealth → SFC | 必要 |
| メモリ使用状況 | 毎サイクル | 手動対応 | - |
| 再起動保留 | 毎サイクル | 手動対応 | - |
| ネットワーク/DNS | 毎サイクル | DNS キャッシュのクリア | 不要 |

## 設定と既定値

設定画面では、自動修復（有効）、通知（修復時のみ）、通知クールダウン（60分）、重複抑制（60分）、点検間隔（5分）、Windows 起動時開始（有効）、ドライラン（無効）、ディスク警告（15% かつ 20GB 未満）・重大（7% かつ 8GB 未満）、メモリ警告（10%）、1日の修復試行上限（3回）、履歴最大件数（1000件）、履歴保持（90日）、コンポーネントストア整理（許可）、監視サービス、点検ごとの有効/無効を変更できます。起動時に Windows のスタートアップ登録を自動で同期します。履歴の剪定は初回追記時と、`max(20, 最大件数 / 10)` 回の追記ごとに遅延実行します。

同じ点検の `Skipped`・`ManualActionRequired`・`Detected` は、結果が同一なら重複抑制期間中は履歴と通知を省略します。`Repaired`・`RepairFailed` は常に履歴へ追記します。通知クールダウンは同じ点検・結果の通知だけに適用され、値 0 で各機能を無効にできます。サイクル完了時刻はトレイの状態行とは独立したメニュー行とツールチップに表示されます。

履歴の上限件数・保持日数の変更はアプリ再起動後に反映されます（`JsonlHistoryStore` は起動時の設定で構築されます）。

## 保存先

- 設定: `%LOCALAPPDATA%\Potion\settings.json`
- 履歴: `%LOCALAPPDATA%\Potion\history.jsonl`
- 点検状態: `%LOCALAPPDATA%\Potion\state.json`（再起動後も点検間隔を維持するための最終点検時刻）
- ログ: `%LOCALAPPDATA%\Potion\logs\tray-yyyyMMdd.log`（30日保持）

## ビルドと実行

```bash
dotnet build Potion.Tray.sln -c Release
dotnet publish src/Potion.Tray -c Release -r win-x64 --self-contained false
```

## CI で実行するコマンド

```bash
dotnet restore Potion.Tray.sln
dotnet build Potion.Tray.sln -c Release --no-restore
dotnet test tests/Potion.Tray.Core.Tests/Potion.Tray.Core.Tests.csproj -c Release --no-build
```

ワークフロー追加は `workflow` スコープを持つ権限が必要なため本 PR には含めません。

Windows 上で `src/Potion.Tray/bin/Release/net8.0-windows/Potion.Tray.exe` を実行します。

## 安全設計

実行できるコマンドは `sfc.exe`、`DISM.exe`、`sc.exe`、`ipconfig.exe`、`cleanmgr.exe` の許可リストに限定されます。引数はシェルを介さず個別に渡し、修復は可逆性を考慮した操作に限定しています。危険な操作は既定で無効化でき、ドライランと1日の試行上限も備えています。

コンポーネントストアの DISM 出力は `/English` を付けて監査履歴を英語に固定します。オプションを受け付けない環境では従来形式でも再確認します。サービスは自動起動（判定不能を含む）の停止状態だけを異常として扱い、手動・無効サービスは対象外です。ネットワーク未接続時は DNS 点検をスキップします。ディスク空き容量はパーセントと絶対値（既定の警告 20GB、重大 8GB）の AND 条件で判定します。

## 多言語対応

対応言語は英語（中立リソース）、日本語、简体中文、한국어、Español、Français、Deutsch、Português (Brasil)、Русскийです。設定の言語が空の場合は OS の UI 言語に追従し、対応するリソースがない場合は英語へフォールバックします。言語を変更した場合は次回起動時から反映されます。

履歴のタイトル・詳細・修復概要・スキップ理由は監査記録のため、記録時の言語で凍結されます。履歴画面の列見出しと列挙値表示は現在の言語で表示します。言語を追加する場合は中立 `Strings.resx` と同じキーを持つ `Strings.<culture>.resx` を1ファイル追加してください。RTL 言語は現在未対応です。
