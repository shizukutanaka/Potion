# Potion.Tray（トレイ常駐アプリ）

Potion.Tray は、Windows の状態を定期的に点検し、許可された安全な修復だけを自動実行するトレイ常駐アプリです。点検結果は履歴に保存され、必要に応じて通知されます。

## 動作の仕組み

1. 設定された間隔で、ディスク、重要サービス、メモリ、再起動保留、DNS、コンポーネントストアを点検します（重いコンポーネントストア点検は最後に実行します）。
2. 問題が見つかった場合、自動修復の設定、管理者権限、1日の試行上限を確認します。
3. 実行したコマンド、結果、出力末尾を履歴へ保存します。
4. 修復が成功した場合は同じ点検を再実行し、問題が残っていれば未検証として履歴に記録します。
5. 通知モードに応じて Windows のバルーン通知を表示します。

スリープ復帰、ユーザーのログオン・ロック解除、ネットワーク復帰時には即時点検を開始します（イベント連発時は2分間デバウンス）。同じユーザーで二重起動した場合は、既存インスタンスの履歴画面を開きます。

初回起動時は常駐開始を通知します。管理者権限なしで起動した場合は、修復には昇格が必要であることを別途通知します。各通知は一度だけ表示し、両方が必要な場合は初回はウェルカム通知、管理者案内は次回起動時に表示します。通知を無効にしている場合は表示しません。

バルーン通知をクリックすると履歴画面を開けます。トレイメニューの「保存フォルダを開く」から、設定・履歴・点検状態・ログ・壊れた設定の退避先を含むデータフォルダを開けます。

## 点検と修復

| 点検 | 既定の間隔 | 修復 | 管理者権限 |
| --- | ---: | --- | :---: |
| ディスク空き容量 | 毎サイクル | 一時ファイル削除、任意でコンポーネント整理 | 不要（一部は必要） |
| 重要サービス | 毎サイクル | 停止サービスの再起動 | 必要 |
| メモリ使用状況 | 毎サイクル | 手動対応 | - |
| 再起動保留 | 毎サイクル | 手動対応 | - |
| ネットワーク/DNS | 毎サイクル | DNS キャッシュのクリア | 不要 |
| コンポーネントストア | 12時間 | DISM RestoreHealth → SFC | 必要 |

## 設定と既定値

設定画面では、自動修復（有効）、通知（修復時のみ）、通知クールダウン（60分）、重複抑制（60分）、点検間隔（5分）、Windows 起動時開始（有効）、ドライラン（無効）、ディスク警告（15% かつ 20GB 未満）・重大（7% かつ 8GB 未満）、メモリ警告（10%）、1日の修復試行上限（3回）、履歴最大件数（1000件）、履歴保持（90日）、コンポーネントストア整理（許可）、DNS 疎通確認先、監視サービス、点検ごとの有効/無効を変更できます。DNS 疎通確認先はホスト名として扱われ、空・空白・空白文字・`/`・`\`・`:` を含む入力は既定値へ戻して確認を求めます。起動時に Windows のスタートアップ登録を自動で同期します。履歴の剪定は初回追記時と、`max(20, 最大件数 / 10)` 回の追記ごとに遅延実行します。

同じ点検の `Skipped`・`ManualActionRequired`・`Detected` は、結果が同一なら重複抑制期間中は履歴と通知を省略します。`Repaired`・`RepairFailed` は常に履歴へ追記します。通知クールダウンは同じ点検・結果の通知だけに適用され、値 0 で各機能を無効にできます。サイクル完了時刻はトレイの状態行とは独立したメニュー行とツールチップに表示されます。

履歴ファイルへ追記できない場合も点検・修復は継続しますが、ログへエラーを記録し、通知が有効なら「履歴を保存できません」という通知をクールダウン付きで表示します。これにより、履歴が空であることとアプリが動作していないことを区別できます。

ディスク不足の修復では、一時ファイルと（管理者権限がある場合の）コンポーネントストアだけを安全に処理します。ごみ箱や Windows Update のダウンロードキャッシュは不可逆な削除やサービス停止を伴うため自動削除せず、容量を多く使っている場所として修復結果の履歴へ表示します。ごみ箱、ダウンロードフォルダー、Windows Update キャッシュ、一時ファイルは各ルート最大20,000ファイルまたは5秒まで計測し、結果は概算です。計測を打ち切った場合は下限値としてサイズに `+` を付けて表示します。

履歴画面では結果フィルターに加えて、タイトル・詳細・修復概要・スキップ理由を対象にした大文字小文字を区別しない検索ができます。一覧の概要列は改行やタブを1行へ整形しますが、詳細ペインと CSV では監査情報の改行を保持します。所要時間は秒または分の小数1桁で表示し、CSV には終了コード付きの実行コマンド列も含めます。

履歴の上限件数・保持日数の変更はアプリ再起動後に反映されます（`JsonlHistoryStore` は起動時の設定で構築されます）。

## 保存先

- 設定: `%LOCALAPPDATA%\Potion\settings.json`
- 履歴: `%LOCALAPPDATA%\Potion\history.jsonl`
- 点検状態: `%LOCALAPPDATA%\Potion\state.json`（再起動後も点検間隔を維持するための最終点検時刻）
- 壊れた設定: `%LOCALAPPDATA%\Potion\settings.invalid-yyyyMMddHHmmss.json`（読み込み失敗時に元ファイルを退避）
- ログ: `%LOCALAPPDATA%\Potion\logs\tray-yyyyMMdd.log`（30日保持）

これらはトレイメニューの「保存フォルダを開く」から確認できます。

## ビルドと実行

配布用には、.NET 8 Desktop Runtime が不要な self-contained 単一 exe を推奨します。

```bash
dotnet build Potion.Tray.sln -c Release
dotnet publish src/Potion.Tray -p:PublishProfile=win-x64
```

発行先の `win-x64` フォルダーにカルチャ別サテライトフォルダーが現れる場合もありますが、単一 exe と同じリソースの重複コピーです。`Potion.Tray.exe` だけを配布すれば9言語が利用できます。空白を含む任意のパス（例: `C:\Program Files\Potion\Potion.Tray.exe`）へ配置でき、初回起動時にユーザー単位の Windows スタートアップへ登録されます。

開発者が .NET 8 Desktop Runtime を別途インストール済みの場合は、self-contained ではない発行も利用できます。

```bash
dotnet publish src/Potion.Tray -c Release -r win-x64 --self-contained false
```

この形式では配布先に .NET 8 Desktop Runtime が必要です。

## CI で実行するコマンド

```bash
dotnet restore Potion.Tray.sln
dotnet build Potion.Tray.sln -c Release --no-restore
dotnet test tests/Potion.Tray.Core.Tests/Potion.Tray.Core.Tests.csproj -c Release --no-build
```

ワークフロー追加は `workflow` スコープを持つ権限が必要なため本 PR には含めません。

Windows 上で `src/Potion.Tray/bin/Release/net8.0-windows/Potion.Tray.exe` を実行します。

## 安全設計

実行できるコマンドは `sfc.exe`、`DISM.exe`、`sc.exe`、`ipconfig.exe` の許可リストに限定されます。引数はシェルを介さず個別に渡し、修復は可逆性を考慮した操作に限定しています。危険な操作は既定で無効化でき、ドライランと1日の試行上限も備えています。

コンポーネントストアの DISM 出力は `/English` を付けて監査履歴を英語に固定します。オプションを受け付けない環境では従来形式でも再確認します。サービスは自動起動（判定不能を含む）の停止状態だけを異常として扱い、手動・無効サービスは対象外です。DNS 点検は設定された疎通確認先を使用し、ネットワーク未接続時はスキップします。設定画面ではホスト名の形式を検証し、URL やパスの誤入力を既定値へ戻してユーザーに確認を求めます。ディスク空き容量はパーセントと絶対値（既定の警告 20GB、重大 8GB）の AND 条件で判定します。

修復回数の1日上限は、監査履歴のカウントとプロセス内メモリカウンターの二重防御です。履歴を書き込めない場合でも、プロセス内で実行回数を数えて上限を守ります。ディスク修復は Critical では更新から1日以上、Warning では7日以上経過した一時ファイルだけを対象にし、`Windows\Temp` は管理者権限がある場合だけ走査します。各ルートの走査は最大50,000ファイルまたは30秒で打ち切ります。

履歴 CSV は、数式として解釈され得る先頭文字（`=`、`+`、`-`、`@`、タブ、復帰）の前にアポストロフィを付けて出力します。

## 多言語対応

対応言語は英語（中立リソース）、日本語、简体中文、한국어、Español、Français、Deutsch、Português (Brasil)、Русскийです。設定の言語が空の場合は OS の UI 言語に追従し、対応するリソースがない場合は英語へフォールバックします。言語変更は再起動なしでトレイメニューへ即時反映されます。

履歴のタイトル・詳細・修復概要・スキップ理由は監査記録のため記録時の言語で凍結され、過去の記述は言語変更によって書き換わりません。履歴画面の列見出しと列挙値表示は現在の言語で表示します。言語を追加する場合は中立 `Strings.resx` と同じキーを持つ `Strings.<culture>.resx` を1ファイル追加してください。RTL 言語は現在未対応です。

メモリ点検で空きメモリが閾値を下回った場合は自動的にプロセスを終了せず、使用量上位3プロセスを判断材料として表示します。

設定画面で入力値が許容範囲外だった場合は、調整された項目を通知して保存を保留します。調整後の値を確認して、もう一度保存してください。すべての点検を無効にして保存する場合は、点検・修復が行われないことを警告して確認します。監視対象に存在しないサービス名が含まれている場合は通知しますが、将来インストールされる可能性があるため保存は続行します。
